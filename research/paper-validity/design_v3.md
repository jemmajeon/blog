## 1. 단일 주 가설
> **H1**: 사전 판정된 "실행 가능 코드 동반" 논문 모집단에서, **MCP 프로토콜로 포장된** 도구 에이전트는 **동일 오프라인 예산으로 검증된 함수 라이브러리를 보유한** 저장소 접근 베이스라인보다 **T3 과제 정확도**가 높다.

- **주 종점 = T3 정확도 차이, 질의시점 예산 1배 수준. 단 하나.**
- **반증 조건**: 그 차이의 95% **BCa 군집 부트스트랩** CI가 0을 포함하면 H1 기각. 기각도 그대로 발표.
- **확증 검정 1개** → 다중성 보정 불필요. 0.5배·2배 수준, T1·T2·ITT·비용·지연·침묵결함·개입원장·§2.3 층화는 **전부 secondary/exploratory**이며 **주 결론에 쓰지 않는다.** 특정 예산 수준에서만 효과가 나타나도 **주 결론을 바꾸지 않는다**(사실은 보고한다).
- **절대 수준 병기 의무**: H1 지지를 서술할 때 **양 팔의 절대 정확도를 반드시 병기**한다. (0.12 vs 0.04도 H1을 만족시킨다는 사실을 본문에 명기)

## 2. 순환 차단

### 2.1 봉인 분할
파이프라인 실행 전 튜토리얼 열거·무작위 분할. 시드·파일 해시를 등록 시 공개 커밋. 사후 변경 불가.

### 2.2 계층 정의 — 생성물 참조 없음
| 계층 | 정의 | 역할 |
|---|---|---|
| T1 재현 | 봉인 튜토리얼 셀 재현 | secondary |
| T2 모수 이동 | 구성 튜토리얼 관측 인자 범위 밖. 작성자: 외부 분석자 2인, 도구 목록 비접근 | secondary |
| **T3 조합** | **논문 Methods가 서로 다른 절로 분리 제시한 분석 2개 이상을 결합해야 답이 나오는 과제.** 판정 근거는 논문 텍스트뿐 | **주 종점** |

- T3 작성: 논문당 외부 도메인 전문가 2인, **논문 Methods만** 열람. 도구 목록·MCP 스펙·저장소 비접근.
- **항목 선별 절대 금지 (§4보다 우선)**: 작성된 T3 과제는 **어떤 이유로도 주 분석에서 제외하지 않는다.** 도구 커버리지 부족, 그림형 답, 정답 도출 불가 — 전부 제외 사유가 아니다. §4의 제외 규칙은 **T1·T2에만** 적용된다.
- **NO-REF 분류 (신설)**: 정답 산출 단계에서 독립 분석자 2인이 **라이브러리로 정답을 도출할 수 없다**고 합의한 항목은 `NO-REF`로 분류한다. 제외하지 않고, **"라이브러리로 답할 수 없음"이라는 취지의 답변만을 정답으로** 채점한다(올바른 거부가 정답). `NO-REF` 비율을 secondary로 보고하며, **20% 초과 시 T3 작성 지침의 실패로 간주해 그 사실을 발표**한다.
- **그림형 답 처리**: 정답이 수치로 표현 가능한지 여부는 **정답 산출 단계에서, 어느 팔의 실행보다 먼저** 판정하고 해시 커밋한다. **어느 팔의 출력도 판정 입력으로 쓰지 않는다.** 그림 재현을 요구하는 부분은 0점 처리하되 항목은 유지한다.

### 2.3 잔여 오염 정량화
- **API 표면 중복도**를 저장소별로 계산. 중복도 ≥ 0.90인 저장소는 **T1·T2** 분석에서 제외(제외 목록 공개).
- **T3에도 중복도를 측정·보고한다(제외하지 않음)**: T3 필요함수 집합 ∩ 팔 A 도구 표면의 중복도를 항목별로 계산해 **사전 등록된 secondary로 층화 보고**한다.
- §14에 "T3 격차가 프로토콜 포장 효과인지 구성 튜토리얼이 Methods 절을 우연히 덮은 결과인지 본 설계는 분리하지 못한다"를 명시.

### 2.4 네트워크 격리
- 구성·평가 전 구간 egress **허용목록 전용**. 대상 저장소의 docs 사이트·GitHub 웹뷰·알려진 미러 명시 차단.
- 취득한 모든 외부 문서를 해시해 §2.1 커밋 해시와 대조. 일치 시 오염 기록.
- **처분**: 오염 확인 저장소는 주 분석 제외(목록 공개). **오염율 10% 초과 시 연구 전체 무효 선언** 후 발표.
- 접근 로그를 파일·네트워크 양쪽 수집. **로그는 비접근을 증명하지 못하며 검출 도구일 뿐임을 본문에 명시.**
- **사전학습 오염은 통제 불가**. 모델 학습 시점 이후 공개된 저장소 부분표본(n=40)의 T3 정확도를 secondary로 별도 보고.

### 2.5 정답 출처
- T1: 봉인 튜토리얼 셀 출력.
- **T2·T3: 독립 인간 분석자 2인이 라이브러리를 직접 사용해 산출. 생성된 MCP 도구 사용 금지.**
- 정답 산출은 **어느 팔의 실행보다 먼저** 완료하고 정답 집합(NO-REF·수치형/그림형 분류 포함)을 **해시 커밋**.
- 정답 산출자 ≠ T3 작성자. 양측 모두 도구 목록 비접근. 산출 코드·절차를 §13에 포함.
- 두 분석자 불일치 시 **제3 분석자 판정**. 3인 모두 도출 실패 시 `NO-REF`.

## 3. 세 개의 팔 — 처리 정의 명확화

| 팔 | 오프라인 준비 허용 범위 | 금지 |
|---|---|---|
| **A 프로토콜 포장** | 검증된 재사용 함수 라이브러리 + **MCP 등록·스키마·디스커버리 계층** | — |
| **B 동일-오프라인** | **검증된 재사용 함수 라이브러리 + 호출 문서 (허용)** | **MCP 등록·스키마·디스커버리 계층만** |
| **C 무준비** | 없음 | — |

- **주 비교 = A vs B → "MCP 프로토콜 포장의 순효과"**
- **B vs C → "오프라인 검증된 실행 능력의 효과"** (secondary)
- A vs C → 두 효과의 합 (secondary). **상호작용은 추정하지 않는다.**
- **팔 B 구축 품질 보장 (신설)**: 팔 B의 준비 파이프라인은 **제3자가 구현**한다. 구현자는 팔 A 구현에 접근하지 않으며, **팔 A보다 높은 성능을 내는 것이 목표**라고 명시적으로 지시받는다.
- **best-of-k 대칭**: A·B 각각 준비 전략 3종을 독립 구현하고, 파일럿이 아닌 **별도 보정 세트**에서 최고 성능안을 채택한다.
- 팔 B의 준비 절차·코드를 §13 사전공개에 포함.
- 프롬프트는 도구 인터페이스 안내 문장을 제외하고 동일. **한쪽만의 프롬프트 금지 조항 없음.** 세 프롬프트 diff 전문 부록 게재.
- 봉인 튜토리얼은 세 팔 모두 **파일시스템 + 네트워크 격리**로 차단(프롬프트 지시로 대체하지 않음).

**예산 (전부 수치 확정)**
- **오프라인 예산 O**: 논문당 토큰 1,500만 / 벽시계 4시간. 실제 소비량 전 팔 보고.
- **질의시점 예산 Q**: 질의당 토큰 200,000 / 벽시계 10분 / 재시도 3회.
- **민감도 분석**: **O와 Q 각각** 0.5·1·2배 3수준에서 주 비교를 반복하고 전부 보고한다. **1배×1배가 유일한 확증 수준**이며 나머지는 secondary.

## 4. 검증 기준의 코드화
- 모든 통과 기준을 `validation.yaml`에 수치 고정, 버전 태그 공개. **Methods 임계값 표는 이 파일에서 자동 생성.**
- 수치 비교: `|a-b|/max(|b|,ε) < 0.01`, ε=1e-12. **1% 근거 명시**: 부동소수점 잡음(~1e-12)이 아니라 라이브러리 버전·BLAS 구현 차이를 흡수하기 위한 값이며, 이 폭이 흡수할 수 있는 오류 유형을 §14에 열거한다. "exactly (with tolerance)" 류 표현 금지.
- **그림**: 플롯 원천 배열을 직렬화해 수치 비교.
  - 이미지 비교를 쓰는 경우에 한해: **양성 클래스를 "불일치 탐지"로 정의**하고, 라벨쌍 집합(일치 300·불일치 300)과 **목표 FPR = 0.01 및 최소 민감도 0.95를 등록 시점에 사전 공개**한다. **오통과율(false-pass)도 함께 등록**한다. 라벨 작성자는 외부·팔 맹검. 사후 임계값 선택 금지.
  - **제외 규칙은 T1·T2에만 적용.** T3는 §2.2가 우선.
- **구현 일치 감사 (신설)**: 실행되는 테스트 단정문이 `validation.yaml`의 값을 **읽어서** 쓰는지 CI에서 검사하고, 하드코딩된 임계값이 있으면 빌드 실패.

## 5. 불확실성
- **주 CI = 논문 단위 BCa 군집 부트스트랩(10,000 재표본). 반증 판정은 이것 하나로 한다.**
- **와일드 군집 부트스트랩은 강건성 확인용 secondary**로만 병기한다. **두 구간이 갈려도 반증 판정은 BCa로 한다.**
- 정확 이항 CI는 단일 팔 비율의 기술 통계로만 사용하며 주 비교 차이에 사용하지 않는다.
- "± 0.0%" 금지. 비율은 항상 n 병기.
- 실행 간 변동·채점자 변동은 분산성분표로 별도 보고하며 주 CI와 섞지 않는다.
- 재표본 해상도 미만 p값은 "p < 1/재표본수"로만 표기.

## 6. 파생 수치·설계 상수의 자동화
- 모든 배수·비율·증감은 결과 테이블에서 스크립트가 계산해 원고에 주입.
- **`power.yaml` 신설**: p_d·ICC·항목수·적격률·α·검정력 목표를 입력으로 두고, **검정력·설계효과·유효항목수·필요 코퍼스를 스크립트가 계산해 본문에 주입**한다. **손으로 쓴 "검정력 0.80"을 금지한다.**
- **검산기**: 원고의 모든 수치는 결과 테이블 또는 `power.yaml`/`experiments.yaml`의 **명명된 셀에 매크로로 결속**되어야 하며, 결속되지 않은 리터럴 수치가 있으면 빌드 실패. 범위: 본문·초록·그림범례·표·부록 전부. 반올림은 매크로 자릿수 인자로 지정.
- **정성 표현 금지**: "약 N배", "거의 두 배" 등 수치 함축 표현 금지.
- 실험 구성은 `experiments.yaml`에 열거하며 본문의 범주·구성 수는 레지스트리에서 자동 생성.

## 7. 맹검 — 방향 전환
- 응답 정규화기가 최종 답변 필드만 남기고 팔 식별 흔적을 제거한다. 제거 규칙: 도구명·코드블록·MCP 언급 + **유효숫자 자릿수 표준화** + **길이 절단(공통 상한)** + 정형 템플릿 재작성.
- **맹검 무결성 검사 (방향 전환)**: 외부 판정자 3인이 정규화된 응답 **400건**의 팔을 추측한다. **추측 정확도의 95% CI 상한이 우연 수준을 넘지 않을 때만 사람 채점을 허용한다.** (v2는 누출이 입증돼야 무효화하는 방향이어서 낮은 검정력이 사람 채점을 보존했다 — 반대로 뒤집는다.)
  - **표본의 팔 구성비를 사전 고정**하고 그에 따른 우연 수준을 명시한다(A/B만이면 1/2, 3팔 균등이면 1/3).
  - **판정 단위는 응답 400건**이며 판정자 3인의 평정은 응답 수준에서 다수결로 집계한다(1,200 판정을 독립으로 취급하지 않는다).
- **두 채점 도구의 등가성 사전 검증 (신설)**: 사람 채점과 자동 정확일치가 T3 답변에서 등가임을 보정 세트에서 입증하지 못하면, **처음부터 자동 정확일치만 사용**한다. 데이터 의존적 도구 전환을 금지한다.
- 채점자: 저자단 외부. 보정 세트 κ < 0.75면 재훈련 또는 교체. 정규화된 답변과 무작위 ID만 열람.
- 불일치는 제3 채점자 판정으로 해소하고 "합의까지 토론"을 쓰지 않는다. 독립 평정 기록 보존.

## 8. 모집단과 ITT
- **모집단 판정**: 무필터 연속 표집 후, 파이프라인과 무관한 사전 체크리스트로 판정(실행 가능 스크립트/노트북 존재 + 데이터 접근 가능 + 라이선스 허용). 판정자는 외부 2인이며 파이프라인 결과를 모른다. κ 보고(평정자 쌍 = 두 판정자 간).
- **H1 모집단 = 이 판정을 통과한 논문.** 주 종점은 이 집합에서 계산.
- **0점 귀속**: "에이전트화 실패"는 **팔 A에만 정의되는 사건**이며 0점은 **팔 A에만** 부과. 팔 B·C는 해당 논문을 정상 시도. "동일 전체 집합"은 **분모 동일**을 뜻한다.
- "에이전트화 실패"의 조작적 정의를 `validation.yaml`에 수치 고정(도구 0개 생성 또는 전 도구 검증 실패).
- **0점을 0-fail(실패)과 0-wrong(오답)으로 분리 기록**한다. 주 종점 계산에는 합산하되 분해를 secondary로 보고.
- 무필터 전체 집합 ITT는 secondary.

## 9. 침묵 결함 주입 — 종점 3개
- 주입 유형: ①효과대립유전자 뒤바꿈 ②좌표 off-by-one ③다중검정 보정 제거 ④정규화 상수 오류 ⑤공변량 누락. 저장소 3 × 5유형 = **15구성**(`experiments.yaml` 등록).
- **종점 1 검출률**: 에이전트 출력이 결함의 **위치 또는 성질을 명시적으로 지시**한 경우만 검출. 단순 실행 실패·모호한 경고는 비검출.
- **종점 2 오경보율**: 무주입 대조군에서 측정.
- **종점 3 전파율 (신설)**: 주입 실행 중 **결함을 지시하지 않은 채** 무주입 정답 대비 **오답을 산출한** 비율.
- **세 수치를 항상 함께 보고하며, 결론 문단에 반드시 병기한다.** 전파율이 사전 등록 상한(20%)을 넘으면 **"신뢰성 관련 주장을 하지 않는다"** 고 사전 선언한다.
- 판정자: 외부 2인, 주입 여부 맹검. 불일치는 제3 판정. 분모: 15구성 × 과제 수.
- 낮은 검출률은 부정적 결과로 그대로 보고. 실행 오류 주입 결과와 합산하지 않는다.

## 10. 자율성 — 측정 (secondary)
- "autonomous" 및 그 동의어("수동 큐레이션 없이", "완전 자동" 등)를 사용하지 않는다.
- 모든 인간 메시지를 4분류: `pointer` / `parameter` / `analytic-content` / `correction`.
- **코딩 매뉴얼은 §15에 따라 파일럿 미접근 제3자가 저작**한다. 판정 규칙 + 경계사례 20건 정답 라벨 포함. 명시 규칙 예 — "분석 선택을 좁히는 자원 지정은 `analytic-content`", "값이 결과를 좌우하는 수치 설정 제공은 `analytic-content`".
- 코더: 외부 2인, 팔 맹검(가능 범위). **코더 간 κ 보고.**
- **재코딩 루프 1회 제한 (신설)**: 매뉴얼 개정-재코딩은 1회만 허용하며, **개정 전 κ를 반드시 함께 보고**한다. 개정 후 κ만 보고하는 것을 금지한다.
- **4개 분류 전부 보고.** "무개입"은 `analytic-content`=0 AND `correction`=0 AND `parameter`=0 인 분석에만 사용.
- 원장 코딩의 팔 맹검이 구조적으로 불완전함을 §14에 명시.

## 11. 재현성 — 정책 권고 없음
- "에이전트화 용이성 = 재현성 척도"를 **주장하지 않는다.**
- **정책 권고 게이트를 삭제한다.** 어떤 조건에서도 "agent availability" 류 정책 권고를 하지 않는다.
- 인간 재현 부분연구는 **순수 기술적 secondary**로만 유지: 부분표본 n=60, 파이프라인 결과를 모르는 외부 대학원생 수준 2인, 논문당 8시간, 성공 기준은 주 그림/표 1건을 상대오차 1% 내 재생산.
- 보고 통계는 **κ가 아니라** 인간 재현을 기준표준으로 한 **민감도·특이도·PPV**. 공통원인(문서화·유지보수 품질) 교란을 §14에 명시.
- 문서 내 모든 κ는 **평정자 쌍을 명시**한다(일괄 점검 대상).

## 12. 표본·검정력 — `power.yaml`에서 자동 산출
- **코퍼스: bioRxiv bioinformatics, 사전 지정 6개월 창, 연속 표집 380편** (문서화 품질·유지보수 무필터).
- 적격률 가정 0.60 → H1 모집단 ≈ 228편.
- **T3 항목 수: 논문당 4개** (작성자 쿼터로 고정).
- **불일치율 p_d를 사전 등록 모수로 명시한다.** 파일럿 또는 문헌 근거를 제시하며, 근거 미확보 시 **보수적으로 조건부 독립 p_d = 0.464**를 채택한다.
- 가정: ICC 0.15, 설계효과 1+(4−1)×0.15 = 1.45. 대응 설계. 기준 정확도 0.60, 탐지 목표 8%p, α=0.05 양측, 목표 검정력 0.80.
- **최악 오염(10%) 후에도 검정력을 유지하도록 표본을 정한다**: 228×0.90 = 205편 → 820항목 → 유효 566 → 검정력 0.800.
- **최소 군집 수: 논문 ≥ 205편.** 미달 시 주 검정을 수행하지 않고 그 사실을 발표한다.
- 소표본 보정: BCa (확증). 군집 205~250 구간에서 와일드 군집 부트스트랩 병기(secondary).
- **위 수치는 전부 `power.yaml`에서 스크립트가 산출해 주입한다.** 본문에 손으로 쓴 값을 두지 않는다.
- 정지규칙: 사전 산출 표본 도달 시 종료. 중간 분석 없음.

## 14. 주장하지 않는 것
- 사전학습 오염은 통제 불가. 부분표본으로 추정만 한다.
- 접근 로그는 비접근을 증명하지 못한다.
- 개입원장 코딩의 팔 맹검은 구조적으로 불완전하다.
- T3는 "논문 내 분리 제시 분석의 결합"으로 정의된 **조작적** 분포밖이며 절대적 분포밖이 아니다.
- **T3 격차가 프로토콜 포장 효과인지, 구성 튜토리얼이 Methods 절을 우연히 덮은 결과인지 분리하지 못한다.**
- **A vs B는 프로토콜 포장의 효과만 식별한다.** 오프라인 검증 실행 능력의 효과는 B vs C이며, **두 효과의 상호작용은 추정하지 않는다.**
- **H1 지지는 절대 사용 가능성에 대해 아무것도 말하지 않는다.** 낮은 절대 정확도에서도 H1은 만족될 수 있다.
- **1% 허용오차가 흡수할 수 있는 오류 유형**(라이브러리 버전 차, BLAS 구현 차)과 흡수해서는 안 되는 유형을 열거한다.
- **본 추정량은 명시된 단일 모델 세대에 색인된다.** 세대 간 불변성을 주장하지 않는다.
- 설계자 맹검(§15)은 감사 가능성 확보이지 독립성 증명이 아니다.

## 15. 설계자 구속 조항 (신설)
- **파일럿-사전 확정 원칙**: 아래 산출물은 **어떤 파일럿 실행보다 먼저** 확정·해시 커밋한다. 이후 변경 시 변경 이력과 사유를 공개하고 해당 분석을 exploratory로 강등한다.
  - T3 작성 지침 / 채점 rubric / `validation.yaml` / `power.yaml` / 개입원장 코딩 매뉴얼 + 경계사례 정답 라벨 / 모집단 판정 체크리스트 / 코퍼스 창(기간·범주) / 예산 수치 / 그림 비교 라벨쌍·임계값
- **대안 경로**: 위 산출물을 **파일럿 결과에 접근하지 않은 제3자**가 저작한다. 어느 경로를 택했는지 명시한다.
- **파일럿 전면 공개**: 수행한 모든 파일럿의 존재·규모·결과를 등록 시점에 공개한다. **미공개 파일럿을 금지한다.**
- 설계자는 요구사항만 기술하고 판정 규칙을 직접 쓰지 않는다.
