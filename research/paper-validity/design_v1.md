# 설계 v1 — 등록보고서(Registered Report)
## 제목
Agentifying research papers: a pre-registered, held-out evaluation with symmetric baselines

## 형식 결정
**Stage 1 등록보고서**로 제출한다. 설계·가설·분석계획·정지규칙을 데이터 수집 **이전에** 심사·수리받고, 이후 계획 이탈은 전부 "사후분석(exploratory)"으로 별도 표기한다.
근거: 원 논문의 확정 결함 3건(배수 산술, 범주 수 불일치, 통계 단위 모순)은 모두 "결과를 본 뒤 작성된 서술"에서 발생했다. 절차 사전 고정은 이 오류군을 구조적으로 발생 불가능하게 만든다.

---

## 1. 단일 주 가설 (H1)
> 실행 가능한 코드를 동반한 논문에 대해, MCP 도구 에이전트는 **정보 접근이 대칭인** 저장소 접근 베이스라인보다, **무필터 코퍼스 전체에 대한 종단(end-to-end) 정확도**가 높다.

- 부 가설·탐색적 분석은 전부 "secondary/exploratory"로 명시하며 주 결론에 사용하지 않는다.
- **반증 조건 사전 명시**: 종단 정확도 차이의 95% CI가 0을 포함하면 H1 기각. 기각도 그대로 발표한다.

---

## 2. F1 대응 — 순환 차단: 2단 봉인(holdout)

### 2.1 튜토리얼 봉인 분할
각 저장소의 튜토리얼 목록을 **파이프라인 실행 전에** 열거하고 무작위 분할한다.
- **구성용(seen)**: 파이프라인이 읽고 도구를 추출·검증하는 데 사용.
- **봉인용(sealed)**: 파이프라인이 **절대 접근하지 못함**. 파일시스템 수준에서 격리하고, 접근 로그를 수집해 위반 여부를 감사한다.
- 분할 시드와 파일 해시를 등록 단계에서 공개 커밋한다. 사후 변경 불가.

### 2.2 벤치마크 출처 규칙
| 계층 | 출처 | 역할 |
|---|---|---|
| **T1 재현** | 봉인 튜토리얼 | 도구가 본 적 없는 셀의 재현 |
| **T2 모수 이동** | 봉인 튜토리얼 + 구성 튜토리얼의 관측 인자 범위 **밖** 인자 | 외삽 |
| **T3 조합·분포밖** | 어떤 튜토리얼에도 동시 등장하지 않은 도구 조합을 요구하는 과제. **생성된 도구 목록을 보지 못한** 도메인 전문가가 논문 Methods만 보고 작성 | **일반화 주 지표** |

- **주 일반화 지표는 T3**로 사전 고정한다. T1/T2를 일반화 근거로 쓰지 않는다.
- T3 작성자는 도구 목록·MCP 스펙에 접근하지 않는다(문서화 및 감사).

### 2.3 봉인-구성 중복도 보고 (잔여 순환의 정량화)
봉인 튜토리얼이 구성 튜토리얼과 동일 API를 호출하면 봉인은 형식적일 수 있다. 따라서
**API 표면 중복도**(봉인 과제가 호출하는 함수 집합 ∩ 구성 과제가 호출하는 함수 집합 / 봉인 과제 함수 집합)를 저장소별로 계산해 보고하고, 정확도를 중복도 구간별로 **층화 보고**한다.

---

## 3. F2 대응 — 베이스라인 대칭성

### 3.1 프롬프트 대칭 규칙
두 팔의 시스템 프롬프트는 **도구 인터페이스 안내 문장을 제외하고 동일**해야 한다.
- 어느 한 팔에만 적용되는 **금지 조항을 두지 않는다.**
- 정보 사용 제한이 필요하면 **양 팔에 동일하게** 적용한다(예: 봉인 튜토리얼은 양 팔 모두 접근 불가 — 파일시스템 격리로 강제하며, 프롬프트 지시로 대체하지 않는다).
- 두 프롬프트의 **diff 전문을 부록에 게재**한다.

### 3.2 정보 예산 대칭
| 항목 | 도구 팔 | 베이스라인 팔 |
|---|---|---|
| 저장소 | 동일 클론 | 동일 클론 |
| 구성 튜토리얼 | 접근 가능 | 접근 가능 |
| 봉인 튜토리얼 | **격리** | **격리** |
| 사전 구축 환경 | 제공 | **동일하게 제공** |
| 시도 예산(토큰·시간·재시도) | 상한 X | **동일 상한 X** |

- 환경 구축 이점은 별도 ablation("환경만 제공한 베이스라인")으로 분리 측정한다.

---

## 4. F3 대응 — 검증 임계값의 코드화
- 모든 통과 기준을 기계가독 설정 파일 `validation.yaml`에 수치로 고정하고 버전 태그와 함께 공개한다.
- **논문 Methods의 임계값 표는 이 파일에서 자동 생성**한다. 본문에 손으로 쓴 수치를 두지 않는다.
- **그림 비교는 이미지 해시를 쓰지 않는다.** 플롯의 **원천 배열(underlying arrays)** 을 직렬화해 수치 비교한다. 이미지 비교가 불가피한 경우, 비교기의 ROC를 일치/불일치 라벨쌍 집합에서 측정해 보고하고, 임계값은 목표 FPR에서 선택한다.
- "exactly (with tolerance)" 같은 자기모순 표현을 금지하고, 상대오차 기준을 단일 정의로 고정한다.

## 5. F4 대응 — 불확실성 단위 단일화
- **주 불확실성 = 질문 수준, 논문 단위 군집 부트스트랩(cluster bootstrap by paper).** 사전 고정.
- 실행 간 변동은 **분산성분표로 별도 보고**하며 주 CI와 섞지 않는다.
- **"± 0.0%" 보고 금지.** 이항 비율은 항상 n과 함께 정확 이항 CI를 병기한다.
- 검정은 군집 부트스트랩 CI로 보고하고, 해상도 한계 미만의 p값(예: 10,000 재표본에서 p<0.0001)은 "p < 1/재표본수"로만 표기한다.

## 6. F5·F6 대응 — 파생 수치·구성 수의 자동 생성
- 모든 배수·비율·증감은 결과 테이블에서 **스크립트가 계산**하며, 원고에 주입된다.
- 원고 빌드시 **검산기(numeric linter)** 가 본문의 모든 수치가 결과 테이블에 존재하는지 대조하고, 불일치 시 빌드 실패.
- 실험 구성은 `experiments.yaml` 레지스트리에 열거하며, 본문의 "N개 범주 / M개 구성" 문장은 레지스트리에서 자동 생성된다.

## 7. F8 대응 — 구조적 맹검
- 에이전트 응답을 **정규화기**가 처리해 최종 답변 필드만 남기고 팔 식별 흔적(도구명, 코드블록, MCP 언급)을 제거한다. 정규화기는 사전 등록한다.
- 채점자는 정규화된 답변과 무작위 ID만 본다.
- 채점자는 **저자단 외부**에서 모집하며, 보정 세트에서 일치도를 먼저 측정한 뒤 본 채점에 투입한다.
- 정규화가 불가능한 과제(코드 제출 필수)는 **자동 정확일치 채점만** 사용하고, 사람 채점을 쓰지 않는다.
- 불일치는 제3 채점자 판정으로 해소하며, "합의까지 토론"을 쓰지 않는다(독립 평정 기록 보존).

## 8. F9 대응 — 종단 지표를 주 지표로
- **주 지표 = ITT(intention-to-treat)**: 표본 논문 **전체**에 대한 정확도. 에이전트화 실패 논문의 질의는 **0점**으로 산입한다.
- 생존분 한정 정확도는 부 지표이며, **항상 ITT와 나란히** 보고한다.
- 베이스라인도 **동일 전체 집합**에서 측정한다(실패 논문 제외 금지).

## 9. F10 대응 — 침묵 오류(silent defect) 주입 실험
실행은 정상 완료되지만 과학적으로 틀린 결함을 주입해 검출률을 측정한다.
- 주입 유형(사전 고정): ① 효과대립유전자 뒤바꿈 ② 좌표 off-by-one ③ 다중검정 보정 제거 ④ 정규화 상수 오류 ⑤ 공변량 누락
- **낮은 검출률은 부정적 결과로 그대로 보고**한다(사전 명시). 이 실험은 방법의 한계를 규정하는 것이 목적이다.
- 기존의 실행 오류 주입은 별도 범주로 구분해 보고하며, 두 결과를 합산하지 않는다.

## 10. F11 대응 — 자율성의 측정 가능한 정의
"autonomous"라는 서술어를 사용하지 않는다. 대신 **개입 원장(intervention ledger)** 을 보고한다.
- 모든 인간 메시지를 기록하고 4분류: `pointer`(자원 지정) / `parameter`(설정) / `analytic-content`(분석 내용 지시) / `correction`(오류 교정)
- 주 보고 지표: **완료 분석당 `analytic-content` + `correction` 개입 횟수**
- 이 값이 0인 분석만 "무개입(unassisted)"으로 표기하며, 그 외에는 개입 횟수를 병기한다.

## 11. F12 대응 — 재현성 척도 주장의 철회
- "에이전트화 용이성 = 재현성 척도"를 **주장하지 않는다.**
- 검증하려면: 부분표본(n=30)에 대해 **파이프라인 결과를 모르는 인간 재현자**가 독립적으로 재현을 시도하고, 그 성패와 에이전트화 성패의 일치도(κ)를 보고한다. κ를 제시하지 못하면 정책 권고(예: "agent availability" 섹션)를 하지 않는다.

---

## 12. 표본·검정력
- 코퍼스: 사전 지정 기간·범주에서 **연속 표집**(문서화 품질·유지보수 상태로 필터링하지 않음). 목표 n은 T3 주 비교에서 8%p 차이를 80% 검정력으로 탐지하도록 사전 산출해 등록한다.
- 정지규칙: 사전 산출 n 도달 시 종료. 중간 분석을 하지 않는다.

## 13. 사전 공개물
등록 시점에 공개: 분할 시드·해시, 양 팔 프롬프트 전문, `validation.yaml`, `experiments.yaml`, 채점 rubric, 정규화기 코드, 분석 스크립트.
