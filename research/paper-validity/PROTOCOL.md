# 프로토콜 — 논문 논리구조 감사 → 반론 설계 → 자기 감사

이 세션에서 실제로 밟은 절차를 그대로 하네스화한 것이다. 다음 논문에 그대로 적용한다.
각 단계는 **입력·산출물·통과 조건·기계 검사**를 갖는다. 통과 조건 없는 단계는 없다.
정책 규칙(R1–R27)과 회귀 대장(REG-001–008)은 `policy/REVISION_POLICY.md`에 있다.

---

## PART A — 대상 논문 감사 (S0–S4)

### S0 원문 확보
- 입력: DOI/URL. 산출: 전문 텍스트 + 부록 + 표 CSV.
- 통과: 전문 문자 수와 절 목록을 기록. **PDF 스크린샷·초록만으로 진행 금지.**
- 실측: HTTP 전부 차단 시 `git clone`(저자 저장소)로 확보했다. 경로를 기록한다.

### S1 주장·전제 인벤토리
- 입력: 전문. 산출: `claims.md` — 모든 수치 주장·인과 주장·방법 전제를 축자 인용과 함께 번호 매김.
- 통과: 각 항목에 (절, 문장 원문, 유형 ∈ {수치, 인과, 정의, 절차}) 3필드. 인용 없는 항목 금지.
- 기계: `paper_lint.py <원문>` 를 **먼저** 돌린다. 산술·범주수·불확실성 단위 불일치는 사람 이전에 기계가 잡는다.

### S2 다축 병렬 탐지
- 입력: S1 인벤토리. 축 5개 이상, 축마다 독립 에이전트 1기. 축 예: 통계·인과식별·측정타당도·재현성·수사(주장-증거 격차).
- 각 에이전트 산출: 후보 결함 목록, 항목마다 **축자 인용 + 실패 시나리오 + 자신감 0–100**.
- 통과: 인용 없는 후보는 폐기. 에이전트 간 중복은 병합하되 원 출처를 남긴다.
- 주의: 에이전트는 환각한다. 이 세션에서 1기가 **존재하지 않는 수치**로 표 불일치를 보고했다(24/24행 대조로 반증). **S3 없이 S2 결과를 보고하지 않는다.**

### S3 적대적 검증 (95% 게이트)
- 입력: S2 후보. 각 후보에 대해 **원 탐지자와 다른** 에이전트가 반증을 시도한다.
- 검증 방법은 후보 유형별로 고정:
  - 수치 → 원문 값에서 **독립 재계산** (스크립트, 출력 보존)
  - 인과/설계 → 반례 시나리오 구성; 설계가 반례를 배제하는 조항이 있는지 축자 확인
  - 정의 → 문서 내 모든 사용례 대조
- 통과: 재검증 후 자신감 ≥95 인 것만 확정. 미달은 "미확정"으로 **별도 보고**, 폐기하지 않는다.
- 실측 교훈: 확정 3건 중 2건에서 **내가 크기를 과대 진술**했다(검정력 0.649, FWER 0.1426 — 조건부 상한을 점값으로). 결함은 유지, 크기는 정정. **점값을 보고할 때 그것이 상한인지 점추정인지 태그한다(R21).**

### S4 치명도 등급 + 보고
- 등급: FATAL(주 결론 무효) / MAJOR(주 결론 약화 또는 재분석 필요) / MINOR(보고 오류).
- 통과: 등급마다 판정 근거 1문장 + 축자 인용. 반증된 후보도 **반증 근거와 함께** 보고한다.
- 산출: `findings/S4_final_report.md`. 자신감 지수를 항목별로 표기.

## PART B — 반론 설계 (R0 → v_n)

### B0 사전 등록 루브릭 (설계 **이전에**)
- `policy/R0_prereg_rubric.md`: 결함 등급 정의, 릴리스 바(FATAL 0 ∧ MAJOR ≤1), 필수 항목 F1–F12, 자기채점 금지, **최저 라운드 점수 채택**.
- 통과: 루브릭 해시를 커밋한 뒤 설계를 시작한다. 설계 후 루브릭 수정은 금지.

### B1 설계 v1
- 입력: S4 확정 결함. 각 결함에 대응하는 조항을 쓴다.
- 기계: `design_lint.py design_v1.md` 통과. `rule_check.py` 로 판정규칙 배타성 확인(R16).

### B2 독립 공격 라운드 (설계 버전마다, 최소 4기)
- 각 기 축: 통계·독립성/식별·**회귀 사냥(전 버전 대비 악화)**·실행가능성.
- 산출: 축마다 ≤6건, 축자 인용 + 실패 시나리오 + 자신감.
- **점수는 이 라운드 이후에만 매긴다(R14).** 공격 전 추정치를 말하지 않는다.
- 실측: 추정 88 → 실측 82 → 다음 라운드 80. 추정은 세 번 반증됐다.

### B3 수정 회계 (라운드마다)
- `policy/REVISION_POLICY.md`에 기록: 고친 건수 / 새로 생긴 건수 / 고유 MAJOR 수.
- **수정이 원래보다 나쁜 것을 만들면 REG-NNN으로 등재**하고 재발 방지 규칙(R)을 추가한다.
- 실측: 7/7 주요 결함이 **조항 쌍의 상호작용**이었다. 조항이 n개면 쌍은 n(n−1)/2. 뺄셈 원칙(R10)의 근거.

### B4 의무 추적 (R15, 버전마다)
- `obligation_diff.py v_n v_{n+1}` → 후보를 (a)유지/(b)의도적 폐기/(c)조용한 소실로 판정한 표를 커밋.
- 통과: **(c) 0건.** 1건이라도 있으면 릴리스 차단.
- 실측: v3→v4에서 8건 (c). 발견은 v4 공격 라운드에서였다 — 이 표가 없어서.

### B5 뺄셈 검사 (R10·R27)
- `design_lint.py --baseline=v<직전 R15 준수 버전>`. 주장 수 감소 확인.
- 기준선 변경은 인자로 **명시**하며 릴리스 노트에 적는다. 린터 로직으로 통과시키지 않는다.
- 실측: 87→68 감소의 56%가 문장 병합이었다(REG-006). **문장 병합은 감소가 아니다.** 장치 수·재량 판단점 수를 병기한다.

### B6 종료 판정
- 다음 중 하나가 될 때까지 B2–B5 반복:
  - 릴리스 바 충족 → 릴리스
  - 신규 결함 수가 2라운드 연속 감소하지 않음 → **수렴 실패 선언**, 원인 진단(R13)
- 실측: 82 → 82 → 80. 재작성 반복이 점수를 올리지 않았다. 원인: 1층(기계 검사) 미구현.

## PART C — 자기 감사 (저자 자신에게 적용)

### C1 자기 오류 대장
- `policy/ERROR_LEDGER.md`: 세션 중 드러난 **자신의** 거짓·과대 진술 전수. 발견 경로와 기계검출 가능성.
- 통과: 항목마다 "잡을 게이트" 명시. 잡을 게이트가 없으면 규칙을 신설한다(R18–R22의 기원).
- **분모는 관측 불가**다. 검출률을 보고하지 않는다. "검출된 것 중 기계화 가능 비율"만 보고한다.

### C2 게이트 교정 (R23)
- `validate_gates.py`: 기지정상 픽스처 0건, 기지결함 픽스처 전건 검출. 기대값은 명시, 게이트를 고쳐 맞춘다.
- 실측: 게이트 구축 구간에서 오류의 38%가 났다. **"작성했다"는 "작동한다"가 아니다.**

### C3 자기집행
- CI(`.github/workflows/paper-validity-gates.yml`)가 매 푸시마다 C2를 재확인한다. 게이트가 조용히 썩는 것을 막는다.

## 적용 순서 요약
```
S0 → S1 → [paper_lint] → S2(≥5축) → S3(95% 게이트, 독립 재검증) → S4
B0(루브릭 해시) → v1 → [design_lint, rule_check] → B2(≥4기 공격) → B3(회계) → B4(R15) → B5(R27) → 점수 → 반복/종료
C1 → C2[validate_gates] → C3[CI]
```
각 단계의 산출물은 저장소에 커밋한다. 컨테이너·세션은 소멸한다.
